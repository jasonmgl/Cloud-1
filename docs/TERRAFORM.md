# Terraform & AWS setup

[Terraform](https://www.terraform.io/) is an infrastructure-as-code tool. It takes a declarative description of cloud resources (a VM, its network, its firewall) and creates, updates, or destroys them to match. It provisions the *infrastructure itself*, the layer below what Ansible configures.

The target is **AWS**, provisioned with Terraform.

## Prerequisites

- An IAM user's access key, set in `.env` (see the main [README](../README.md)).
- `scripts/install.sh` installs the AWS CLI, `mise`, and Terraform (via `mise use --global terraform@latest`) locally. `make up` runs it automatically.
- `scripts/login_aws.sh` writes `~/.aws/credentials`/`~/.aws/config` from `.env`. `make up` runs it automatically too.

## Implementation

### `terraform/versions.tf`

- Providers: `aws`, `local`, `tls`, `ansible` and `cloudflare`. The `ansible` provider is declared for future use and isn't referenced by any resource yet.

### `terraform/variable.tf`

- `instance_groups` is a nested map (group name → instances), not a flat list, so one Terraform config can stand up several named groups of servers side by side (e.g. a `web` group and a separate group for another role) instead of being limited to a single instance.
- `ssh_allowed_cidr` defaults to `0.0.0.0/0` but exists as its own variable so SSH access can be locked down to a specific CIDR without touching the security group logic itself.
- `ssh_private_key_path` is where Terraform writes the private key it generates (see `main.tf` below), not a path to a pre-existing key.
- `domain_name` is empty by default, so the instance stays reachable by bare IP with a self-signed certificate unless a real domain is set. Can be a subdomain of `cloudflare_zone_name`.
- `cloudflare_zone_name` is the registered root domain (the actual Cloudflare zone), required only when `domain_name` is set.
- `dns_target_instance` picks which instance (`group.instance` key, e.g. `web.1`) `domain_name` points at, since `instance_groups` can define more than one.

### `terraform/main.tf`

- The SSH key pair is generated by Terraform itself (`tls_private_key` + `aws_key_pair`), then written locally via `local_sensitive_file` at `ssh_private_key_path`. This makes the whole pipeline self-contained from a fresh clone with no pre-existing local key assumed, at the cost of a new key pair being generated every time the state is recreated from scratch.
- `aws_eip` allocates a stable Elastic IP per instance. A plain EC2 instance's public IP can change across a stop/start cycle; the Elastic IP keeps it fixed, which matters since `local_file.ansible_inventory` (below) bakes that IP into the generated inventory.
- Each instance group gets its own `aws_security_group`, not one shared group, so groups with different roles could eventually get different ingress rules.
- `user_data` installs `python3` on first boot, since Ansible needs a Python interpreter on the target to run its modules.
- `local_file.ansible_inventory` writes `ansible/inventory.ini` directly (INI format) with both a flat `[aws]` group (every instance, regardless of group) and one section per instance group (e.g. `[web]`). `playbook.yaml` targets the `web` group specifically; `[aws]` exists for `make test`'s `ansible aws -m ping`, a quick connectivity check across every provisioned instance regardless of group.

### `terraform/dns.tf`

- `data "cloudflare_zone" "this"` looks up the Cloudflare zone by `cloudflare_zone_name` (the registered root domain), so `domain_name` itself can be a subdomain of that zone (e.g. `cloud1.example.com` under the `example.com` zone) without needing a manually looked-up zone ID.
- Both the data source and `resource "cloudflare_dns_record" "this"` use `count = var.domain_name != "" ? 1 : 0`, so nothing Cloudflare-related runs at all when no domain is configured. The default (bare IP, self-signed cert) path stays untouched.
- `content` (the record's target IP) is read from `aws_eip.instances[var.dns_target_instance]`, the same Elastic IP `main.tf` already allocates, rather than a separately-tracked value: one source of truth for "what IP does this domain point at."
- `ttl = 1` (Time To Live) is Cloudflare's special value for "Automatic" TTL, not literally one second; Cloudflare picks the caching duration itself.
- `proxied = false`: the record must stay "DNS only", not proxied through Cloudflare's edge. A proxied record would terminate TLS at Cloudflare instead of this project's own `nginx`/certbot setup.


### `terraform/output.tf`

- Outputs are keyed by group and instance (`instance_public_ips.web["1"]`, etc.), matching the nested shape of `instance_groups`.
- `ssh_commands` outputs a ready-to-run `ssh -i ... user@ip` string per instance, so connecting manually doesn't require reconstructing the command from other outputs by hand.

### `terraform/actions.tf`

- `action "aws_ec2_stop_instance" "force_stop"` is a Terraform *action* (invoked directly, not a resource reconciled by plan/apply). `force = true` stops the instance without waiting for a graceful OS shutdown. `make down` invokes it with `terraform apply -invoke=action.aws_ec2_stop_instance.force_stop`.
- This is separate from `instance_power_state` (`variable.tf`): that variable is the declarative state Terraform reconciles toward on every `apply`, while the action is a one-off "stop now" that doesn't require changing any variable first.

### `Makefile`

- `make up` runs `scripts/install.sh`, `scripts/login_aws.sh`, `scripts/init_terraform.sh`, `scripts/provision_ec2.sh`, then `scripts/init_ansible.sh` in sequence: local tools, AWS credentials, Terraform init, `terraform apply`, then the Ansible playbook.
- `make down` stops the instances via the `actions.tf` action above, without destroying them.
- `make destroy` runs `terraform destroy`.
- `make fclean` destroys the infrastructure and also uninstalls the local tools `scripts/install.sh` installed.
